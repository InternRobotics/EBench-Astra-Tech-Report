# EBench–Astra 报告：贡献定位与研究启发审阅

审阅版本：`809fe38`；日期：2026-09-19。只读审阅网页、`docs/REPORT-COPY.md`、`analysis/latex-review/analysis.tex` 及相关原始记录，没有修改网页，也没有启动新实验。外部校准仅使用原始论文或官方项目资料；以下实验、数据集和指标建议均是待实施方案。

## 1. 总体判断

报告已有值得发布的实证基础：在明确的 RGB + 机器人状态、单示教 ICL、直接 EEF 请求接口下，Astra 在 26 个任务上的能力分布与七个专用策略形成了有解释力的差异；视频与公开动作说明又让读者看到成功率背后的执行过程。最强的贡献不是“首次提出大模型与机器人结合”，也不是“证明 agent 全面替代 VLA”，而是**诊断一种控制方式在哪里已经可用、在哪里失效，以及应该如何评价它的适应能力**。

目前三个核心问题覆盖完整，但贡献的证据强度不均：

| 核心问题 | 已有证据 | 可以成立的贡献 | 目前还不能当作已验证贡献的部分 |
| --- | --- | --- | --- |
| Astra 与传统策略各自强弱 | 26 任务主表、精度/移动/时长分组、teacup 与 glasses 视频 | 具体评测条件下的能力分布与排名反转；目标修复和精细执行的互补案例 | “推理模型普遍优于策略”“移动本身导致优势”“传统策略没有纠错能力” |
| 失败规律与启示 | 精度下降、长程完成下降、Score/SR 分离、接触和重试案例 | 从总成功率走向执行阶段诊断；区分局部修复与任务完成 | 深度估计差、反馈慢、重试浪费是各类失败的已确认原因；增加时间或混合控制必然有效 |
| 探索、纠错、总结的新能力 | Apple006 的公开说明、实际策略改变与成功终态；teacup 的目标失效后恢复 | episode 内基于经历修订执行策略的可追踪案例 | 跨 episode 累积学习、普遍恢复优势、解释忠实性、RSI 已被实现 |

建议贡献定位为：**“可审计的能力诊断 + 失败后的适应过程证据 + 面向后续研究的评测接口/数据资产”**。如果只保留现有四条愿景，读者会赞同但难以指出本报告改变了哪个研究问题；若将其落实为下面的转折点标注与受控恢复评测，社区贡献会清楚得多。

## 2. 与已有工作的关系：方向成立，但概念本身并非新提出

| 当前结论方向 | 已有工作已覆盖的内容 | 本报告可以形成的区别 |
| --- | --- | --- |
| Agent 与低层策略协作 | SayCan 将语言规划与可执行技能/affordance 结合；RPent 把 VLA 技能放进 agent 的工具接口，并返回执行反馈。 | 用当前 EBench 的具体失败状态回答“何时交接控制”：目标失效、接触不确定、连续重试、预算不足，而不只展示一个分层系统框图。 |
| 根据反馈重规划、自主纠错 | Inner Monologue 已研究成功检测、场景描述等反馈带来的闭环重规划，包括人为扰动后的恢复。 | 本报告的直接 RGB/机器人状态条件、无中间评分/子目标信号、直接 EEF 请求与精细接触失败，可支持更严格的“能否自行识别需要恢复的状态”评测。 |
| 强模型的策略教给小策略 | ECoT 用合成的计划、子任务、视觉和动作相关推理训练 VLA；ECoT-Lite 进一步研究不在测试时生成推理仍获得收益的训练方式。 | 从成功示教的解释转向**失败状态下的干预选择**：何时看、如何重抓、何时改变搬运方式、何时交回局部控制。价值应由恢复表现和推理成本的对照体现。 |
| 总结经验、工具积累、RSI | Reflexion 已使用反思文本记忆指导后续尝试；Voyager 已用反馈迭代程序并积累可复用技能库，还测试跨环境/agent 的复用。 | 将经验约束到真实接触几何、机器人构型、适用前提和危险条件；证明从一个失败转折点学到的工具能在未见状态或另一模型上稳定获益。 |

上述对应关系只用于定位，不把这些论文的性能结果迁移为本报告的证据。[SayCan 官方项目](https://say-can.github.io/)、[RPent 架构](https://rpent.readthedocs.io/en/latest/rst_source/development/architecture.html)、[Inner Monologue 官方项目](https://innermonologue.github.io/)、[ECoT 官方项目](https://embodied-cot.github.io/)、[ECoT-Lite 官方项目](https://ecot-lite.github.io/)、[Reflexion 原论文](https://arxiv.org/abs/2303.11366)、[Voyager 官方项目](https://voyager.minedojo.org/)。

特别注意：当前报告所称“新能力”，最好指**这次 Astra 评测中展现出来的能力**，而不是该能力在具身研究史上第一次出现。VLA 也可以包含推理、记忆、反馈与分层执行，不能把“agent”和“VLA”描述成互斥的智能种类。

## 3. 最值得强化的五点

### 3.1 Finding：差别发生在执行需求上，不是一个总榜名次

**当前证据。** Astra 总体第二，但低精度到高精度 SR 从 60.60% 降到 11.25%，排名从第二变成第七；移动任务与 OpenWAM-α 差 3.60 pp，桌面任务差 22.14 pp；长程任务 28.10%，OpenWAM-α 为 51.43%。这些交叉变化比“总体第二”更能指导研究者选择技术路线。

对 `dist/data/tasks.json` 的任务级 SR 独立复算也显示这种非一致优势：Astra 相对 OpenWAM-α 的胜/平/负为 7/5/14，相对 Qwen-RobotManip 为 12/4/10，相对 π₀.₅ 为 14/2/10。该描述适合放在能力分布中，不能替代差值大小、显著性分析或泛化保证。

**建议强化。** 不要仅重复三个柱状图。为每个任务展示 Astra 相对同一固定参照 OpenWAM-α 的差值，并用精度、时长、移动属性共同标注。这样能看到究竟哪些任务贡献了差距，而不是把 mobile、precision、horizon 当成相互独立的实验因素。

**可检验问题。** 在控制任务构成后，Astra 的相对差距是否仍与精度要求相关？先发布 26 任务交叉属性表，检查移动任务是否恰好以较低精度任务为主；做分层描述和敏感性分析，再决定是否有足够任务支持回归。只有 26 个任务，不能用一个复杂回归宣称已经识别能力机制。

**统计建议。** 保留 task-macro 主指标；同时显示每任务样本数与区间。对模型差值用任务级重采样评估任务构成敏感性；若所有模型 episode seed 和评测版本已确认一致，再做同 seed 的配对比较。任务选择固定时，跨任务 bootstrap 表示对任务构成的敏感性，不是任意真实机器人任务上的置信保证。mixed 仅两次成功的领先不应成为主 finding。

**社区产物。** 一份有版本号、任务属性、分母、条件和可复算脚本的 capability profile，而不是只能截图的排行榜。读者应能选择自己的任务需求，查看对应策略表现与失败视频。

### 3.2 Finding：局部恢复与完整任务成功可以分离，需要衡量恢复的净收益

**当前证据。** 273 个未完成 episode 中，188 个仍有正 partial Score；peg、nut、dishwasher 都呈现部分进度与最终成功之间的落差。Teacup 中目标被后续操作破坏后再次进入计划，Apple006 中修复了滑落并最终成功。与此同时，coffee 的多轮接触调整没有完成任务。

**建议把恢复拆成五个可以标注的事件。** 失败/目标失效发生 → 模型检测或提出怀疑 → 获取新观测或改变策略 → 对应状态实际修复 → 整个任务完成。不能用“发生多次重试”直接代替恢复，也不能用模型说“抓住了”代替客观状态恢复。

**离线可做。** 在现有视频与 public action records 中，对正反案例标注这些转折点。每个事件保留 call、sim step、视频时间、可见证据、原始 action reason、人工判断及不确定性。视频时间不能直接当成 simulator 时间；缺少稳定对齐时应明确标注区间。先按任务和终态分层抽样，再扩展，公布抽样规则，避免只选会纠错的成功片段。

**指标。** 检测延迟；局部修复率；修复后终局成功率；修复所耗仿真步数/调用数；修复中破坏既有目标的比例。统计分母应是明确的 eligible failure events。positive Score 仅能证明评分规则下的部分信用，不能自动推出“已经正确识别目标”或“曾经单调取得进展”。

**下一步实验。** 在可重放的同一状态注入相同扰动，如轻微改变物体位姿、使已放好的杯子离开目标区域、一次抓取未抓住。对 agent 与策略同时测量状态修复和终局成功。自然运行中 Astra 可能先制造更多失误，因此只比较“自然发生失败后的恢复率”会有选择偏差；标准化扰动用于研究恢复能力，自然 episode 用于研究完整系统表现，两者都应保留。

**社区产物。** 失败转折点标注集 + 恢复指标脚本。进一步提供可以还原接触、速度、对象和机器人状态的检查点；若现有日志不足以精确恢复，先称“对齐事件数据”，不能称可重放 benchmark。

### 3.3 Finding：Apple006 的关键不是说出一句反思，而是改变了下一次控制策略

**当前证据。** 同一个 episode 中，call 9 用底盘搬运，call 10 依据夹爪间距怀疑滑落，call 11 退开扩大视野，call 12 重定位，call 17 明确改为 arm-only transport，后续服务端确认成功。历史示教原本包含底盘平移。这是“参考示教 → 遇到失败 → 修改执行方式”的具体可审计链条。

**强项与边界。** 原始 `reason` 不是隐藏推理，但它与后续动作参数、终态可以相互核对。当前链条支持 episode 内经验使用，不单独证明其文字解释是决定下一步的原因，也不证明底盘运动是滑落唯一原因。共享提示已有抓握验证和重试指导，创新点不能写成模型自行发现一厘米测试抬升。

**下一步对照。** 从失败后的同一可重放状态比较：完整历史、仅当前观测、当前观测 + 精简失败摘要、当前观测 + 等长度但无关摘要；锁定 demonstration、动作接口和预算。还可以比较是否允许主动选择相机/换视角。主要终点是修复和任务成功；辅以视野覆盖/目标可见度、下一次抓取稳定性与成本。让实验检验“历史中的有用经验是否改善执行”，而不是仅观察是否生成了更长解释。移除文本会改变上下文分布，因此不要把单一提示删除实验解释为内部机制的定论。

**值得突出的区别。** Inner Monologue 已证明环境反馈支持重规划；本项目可进一步研究接触失败后，agent 在没有中间评分和物体 GT 的输入条件下，能否主动获取足够观测并修改连续控制方案。这是更具体的问题。[Inner Monologue 官方证据范围](https://innermonologue.github.io/)。

**社区产物。** Apple006 式“失败前方案—观测—修订方案—结果”的统一数据格式，既保存成功恢复，也保存错误诊断和无效重试。公开动作说明与人工验证标签必须分栏。

### 3.4 研究方向：让小策略学习何时改变策略，比泛称“意图模仿”更有贡献

**当前已有。** Astra 产生了观察、重抓、改变移动方式等序列，并能结合一次示教调整操作。当前没有学生策略训练或迁移评测，所以这一项仍是研究倡议。

**建议明确训练对象。** 学习状态变化到策略选择的映射，例如继续执行 / 获得新视角 / 局部重抓 / 改变接近方向 / 重置子目标 / 请求更强 agent。预测中间目标、可见的失败征兆和所选操作，而不是把所有语言 reason 都当成真实因果标签。教师最终成功不代表每个中间动作都值得模仿。

**最低有区分度的实验。** 同一 student、同一数据量和训练预算下比较：A 成功轨迹动作模仿；B 加失败恢复动作但不加语言；C 加通用任务/子目标语言；D 加与实际失败转折点对齐的状态诊断和策略选择；E 含错误/打乱解释的负对照。报告在未见扰动和未见任务组合上的恢复、终局完成、动作成本与干预次数，并检查正常状态性能是否下降。

**与既有工作的区别。** ECoT 已将结构化推理用于 VLA 训练，因此“让策略学会推理”不足以成为新贡献。ECoT-Lite 已展示无需测试时生成完整推理的训练路线；本项目更有价值的是验证失败状态下的选择知识是否可被蒸馏，以及何时才需要调用强模型。上述训练对照能区分收益究竟来自更多恢复动作，还是来自诊断/策略监督。[ECoT](https://embodied-cot.github.io/)、[ECoT-Lite](https://ecot-lite.github.io/)。

**社区产物。** 有状态/动作对齐的恢复训练切片、负例标签、固定 train/test 扰动划分、统一 student baseline。相比仅发布几段“很聪明”的视频，这会直接支持后续工作。

### 3.5 研究方向：用有适用前提的经验工具与受限执行，连接 RSI、效率和安全

**当前已有。** 公开记录能支撑 episode 内修改策略。三个选定 episode 的仿真时间分别为 34.70、116.67、66.67 秒，policy wall duration 为 729.84、5050.40、2658.43 秒；最长无新模型观察的 action batch 分别覆盖 2.13、6.40、4.00 仿真秒。它们为讨论动作/观测粒度提供了实数依据，但不是全队列时延统计。

**具体研究对象。** 把经验保存为带前提和反例的工具，例如“检测到疑似滑落时先将空手移开、获取更广视野、重定位后再抓取”；把“避免底盘移动”保存为条件化候选策略，不能普适化为永远不移动底盘。工具需包含适用物体/机器人条件、必需观测、退出条件、完成检查和危险边界。

**验证路径。** 固定初始模型；分离经验收集集、工具选择/调参集和最终保留测试集；比较无记忆、原始日志检索、精简经验检索、可执行工具四种条件。测量新状态成功率、负迁移、平均成本、危险事件和另一 base model 上的迁移。跨 episode 记忆获益先称经验迁移；只有形成生成—验证—更新过程，且修改后系统在独立测试上持续获益，才逐步讨论更强意义的自我改进，不要仅以“产生了工具”认定 RSI。

**与既有工作的区别。** Reflexion 已研究反思文本的跨尝试使用；Voyager 已研究工具/技能库、反馈修订和复用。这里有潜力的增量是物理执行中的适用前提验证、接触失败与安全约束，以及向其他底层模型/机器人配置迁移的边界。[Reflexion](https://arxiv.org/abs/2303.11366)、[Voyager](https://voyager.minedojo.org/)。

**效率与安全建议。** 分开报告模型请求等待、工具执行 wall time、仿真运动时间和观测间隔；wall/sim 比值不能当作纯推理延迟。同步/异步执行要明确，因为暂停仿真等待模型并不代表真实机器人可以忽略等待。关节位置差分目前只得到片段平均速度；八步采样、角度展开、joint 映射、URDF 版本和约束范围都应对齐后再谈限速比例。没有力数据时不能从速度推算接触力。完整执行日志可以研究这些问题，不应因为未做真机就放弃量化，也不能从可执行 EEF 目标直接认定轨迹安全。

**更有区分度的实验。** 扫描 action batch 长度和反馈频率，在相同 physics budget 下记录成功、滑落、既有目标破坏与调用成本；再比较 direct EEF、固定 skill-hybrid、带失败触发交接的 hybrid。安全监控/动作限幅作用于所有条件，不能只给 hybrid 更好的传感器或无限预算后声称结构优越。

## 4. 当前文案最需要修正的地方

1. **Introduction 与结果不一致。** “effortlessly bypass ... visual distractors, complex instruction following, and policy composition” 已经预支了结论。instruction 组并未领先、POC 尚未形成确认结论，而正文反复解释失败。建议保持兴奋感，但改成“这些表现使我们重新检验强通用模型能否克服……”，把待回答的问题留给数据。范式转变/社区共识/难以想象的能力也需要来源或降为作者观察，不宜用作技术贡献论证。
2. **结论中的 priors、空间理解应与解释层级一致。** 已有结果与这些能力相符，却没有消融把它们从提示、示教、接口和预算中分离。可以写“a capability profile consistent with useful task understanding and spatial reasoning”，不要让首段比正文更因果化。
3. **“rapid feedback”是机制假设与设计要求。** 已有 action-batch 时间可显示观察间隔；尚不能据此把整个精细操作缺口归因于模型慢。将其与几何不确定、接触控制一起作为可测试解释。
4. **减少每段末尾的重复否定，集中成证据层级。** 保留关键边界即可。重要的是在同一处清楚分出“观测到什么—为什么值得研究—接下来怎么验证”，不要让文字读起来像一串免责条款。Apple006 可正面讲完整过程，不必再削弱为泛泛的“可能有帮助”。
5. **结论四个方向要有各自的验证条件。** Agent+policy 对应失败触发控制交接；意图模仿对应失败状态策略监督；RSI 对应保留集上累计收益；安全对应时间/轨迹/事件检查。没有这些可检验对象，四段都容易变成任何机器人文章通用的展望。
6. **公开贡献的动词分级。** 当前可写“we evaluate / document / release”；已设计但未运行写“we propose to test / motivate”。POC 的未见组合、重训原子技能、无测试示教条件保持独立，不能为展示强模型而混入 510 主队列。

## 5. 建议的最小推进方案

**先完成，不要求新评测：** 整理现有任务属性交叉表；将每个主 finding 绑定图、视频和条件；从现有记录建立统一恢复事件格式，至少同时覆盖成功修复、无效重试和修复后仍失败；发布关键统计可复算脚本与证据索引。完善作者已经拥有的日志字段和动作—视频对齐，不把未检查的字段误说成不存在。

**下一轮最优先新实验：** 选移动搬运、精细装配、长程任务各一类，构建相同扰动状态下的恢复比较；锁定示教与预算，分别测检测、局部修复、最终完成。这个实验比扩大更多不受控 demo 更直接回答第二、第三个核心问题。

**随后做一种方法闭环：** 在“失败触发 agent/policy 交接”和“恢复策略蒸馏”中选一个，运行有公平成本控制的最小对照。RSI/工具积累可以保留为明确后续路线，不必同时实现四个方向才能发表诊断性报告。

**建议对外贡献陈述：** 本报告刻画通用多模态模型在直接机器人控制中的能力边界，发现其较强的移动任务表现与精细/长程完成缺口并存；通过对齐视频、公开动作说明和终态结果，展示失败检测、主动观察、策略修订与任务完成之间的联系和断点；这些证据支持进一步建立以失败状态恢复为中心的评测与训练资源。前两项已有实证，最后一项在相应资源整理发布前应写成后续计划。
